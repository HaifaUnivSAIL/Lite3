# Lite3 RL Workspace

This repository is a workspace that bundles multiple Lite3-related stacks: a legacy Isaac Gym training pipeline, a newer Isaac Lab training pipeline, and a C++ deployment SDK (plus robot model assets). It is not a single installable package; use the subprojects directly.

**Structure Review**
| Path | What it is |
| --- | --- |
| `Lite3_rl_training/` | Legacy Isaac Gym training stack for Lite3 (legged_gym + rsl_rl + W&B helpers + debug tools). |
| `rl_training_new/` | Isaac Lab / Isaac Sim training stack with RSL-RL, Docker support, and multiple robot tasks. |
| `Lite3_rl_deploy/` | C++ deployment SDK for sim/real robot control, policy runner, and input interfaces. |
| `rl_training_new/deep_robotics_model/` | Robot model assets (USD/URDF/MJCF). |
| `setup_Lite3_rl_training.sh` | Conda/venv bootstrap for the legacy Isaac Gym stack. |
| `legged_gym/logs/` | Top-level log output directory (generated by past runs). |

Notes:
- `Lite3_rl_deploy/` is tracked as a git submodule. Use `git submodule update --init --recursive` after cloning.
- Log and build folders are generated during runs (`Lite3_rl_training/legged_gym/logs/`, `rl_training_new/logs/`, `Lite3_rl_deploy/build/`).

**Installation Guide**
Choose one training stack, then install deploy tools if you plan to run policies outside training.

Isaac Lab stack (recommended, `rl_training_new/`):
1. Install Isaac Lab (conda install recommended). Follow the upstream Isaac Lab installation guide.
2. From this repo, install the extension using the Isaac Lab Python interpreter:

```bash
cd rl_training_new
python -m pip install -e source/rl_training
```

3. Verify task registration:

```bash
python scripts/tools/list_envs.py
```

Legacy Isaac Gym stack (`Lite3_rl_training/`):
1. Ensure you have Python 3.6 to 3.8 and a compatible CUDA + PyTorch install.
2. Place Isaac Gym (preview 3 or later) under `Lite3_rl_training/isaacgym/`.
3. Use the bootstrap script or install manually:

```bash
./setup_Lite3_rl_training.sh
source venv/bin/activate
```

4. Install the in-tree packages:

```bash
cd Lite3_rl_training/legged_gym
pip install -e .

cd ../rsl_rl
pip install -e .
```

Deployment SDK (`Lite3_rl_deploy/`):
1. Install simulator deps as needed (PyBullet or MuJoCo).
2. Build with CMake for your target platform.
3. See `Lite3_rl_deploy/README_EN.md` for full dependency lists and platform-specific notes.

**Training and Deploy Runs Guide**

Isaac Lab training (recommended stack):

```bash
cd rl_training_new

# Train
python scripts/reinforcement_learning/rsl_rl/train.py \
  --task=TwoLegStand-Deeprobotics-Lite3-v0 \
  --headless

# Play
python scripts/reinforcement_learning/rsl_rl/play.py \
  --task=TwoLegStand-Deeprobotics-Lite3-v0 \
  --load_run <run_folder> \
  --checkpoint <model_XXXX.pt>
```

Logs for Isaac Lab runs:
- `rl_training_new/logs/rsl_rl/<experiment_name>/<timestamp>_<run_name>/`

Legacy Isaac Gym training:

```bash
# From repo root
python Lite3_rl_training/legged_gym/legged_gym/scripts/train.py \
  --task lite3_two_leg_stand \
  --headless

python Lite3_rl_training/legged_gym/legged_gym/scripts/play.py \
  --task lite3_two_leg_stand \
  --load_run <run_name> \
  --checkpoint <model_XXXX.pt>
```

Logs for legacy runs:
- `Lite3_rl_training/legged_gym/logs/<experiment>/<run_name>/`

Deploy (sim-to-sim, x86 example):

```bash
cd Lite3_rl_deploy
mkdir -p build && cd build
cmake .. -DBUILD_PLATFORM=x86 -DBUILD_SIM=ON -DSEND_REMOTE=OFF
make -j
```

Run (two terminals):

```bash
# Terminal 1 (choose one)
cd Lite3_rl_deploy/interface/robot/simulation
python pybullet_simulation.py
# or
python mujoco_simulation.py
```

```bash
# Terminal 2
cd Lite3_rl_deploy/build
./rl_deploy
```

Deploy (sim-to-real, arm example):

```bash
cd Lite3_rl_deploy
mkdir -p build && cd build
cmake .. -DBUILD_PLATFORM=arm -DBUILD_SIM=OFF -DSEND_REMOTE=OFF
make -j
./rl_deploy
```

Policy conversion (PyTorch to ONNX for deploy):

```bash
cd Lite3_rl_deploy/policy
python pt2onnx.py \
  --ckpt /path/to/model_XXXX.pt \
  --out ppo/policy.onnx \
  --num-obs 117 \
  --history-len 40
```
Note: the num-obs and history-len can change depending on the algo architecture.

Default deploy policy path:
- `Lite3_rl_deploy/policy/ppo/policy.onnx`
