# Lite3 RL Workspace

This repository is a workspace that bundles multiple Lite3-related stacks: a legacy Isaac Gym training pipeline, a newer Isaac Lab training pipeline, and a C++ deployment SDK (plus robot model assets). It is not a single installable package; use the subprojects directly.

## Repository layout

| Path | What it is |
| --- | --- |
| `Lite3_rl_training/` | Legacy Isaac Gym + legged_gym + rsl_rl training stack for Lite3 (plus W&B helpers and debug tools). |
| `rl_training_new/` | Isaac Lab / Isaac Sim training stack with RSL-RL (Lite3, M20, etc.) and Docker support. |
| `Lite3_rl_deploy/` | C++ deployment SDK for sim/real robot (pybullet/mujoco sims, gamepad input, policy runner). |
| `rl_training_new/deep_robotics_model/` | Robot model assets (USD/URDF/MJCF for Lite3, M20, X30). |
| `setup_Lite3_rl_training.sh` | Conda bootstrap script for the legacy Isaac Gym stack. |
| `legged_gym/logs/` | Top-level log output directory (generated by past runs). |

## Choose your training stack

Use this quick chooser:

| If you want... | Use this stack |
| --- | --- |
| Isaac Lab / Isaac Sim, newer tasks/configs, Docker workflows | `rl_training_new/` |
| Legacy Isaac Gym (Preview) + legged_gym workflows | `Lite3_rl_training/` |

### A) Isaac Lab (recommended)

Location: `rl_training_new/`

Docs to read first:
- `rl_training_new/README.md`
- `rl_training_new/RUN_PLAY_GUIDE.md`
- `rl_training_new/INSTALL_DOCKER.md` (if using Docker)

Quick sanity check (from `rl_training_new/`):

```bash
python scripts/reinforcement_learning/rsl_rl/train.py \
  --task=TwoLegStand-Deeprobotics-Lite3-v0 \
  --headless
```

```bash
python scripts/reinforcement_learning/rsl_rl/play.py \
  --task=TwoLegStand-Deeprobotics-Lite3-v0 \
  --load_run <run_folder> \
  --checkpoint <model_XXXX.pt>
```

To list all available environments:

```bash
python scripts/tools/list_envs.py
```

Default logs/checkpoints live under `rl_training_new/logs/rsl_rl/`.

### B) Legacy Isaac Gym

Location: `Lite3_rl_training/`

Docs to read first:
- `Lite3_rl_training/README.md`
- `Lite3_rl_training/TRAINING.md`
- `Lite3_rl_training/TRAINING_STACK_GUIDE.md`


Quick sanity check (from repo root):

```bash
python Lite3_rl_training/legged_gym/legged_gym/scripts/train.py \
  --task lite3_two_leg_stand \
  --headless
```

```bash
python Lite3_rl_training/legged_gym/legged_gym/scripts/play.py \
  --task lite3_two_leg_stand \
  --load_run <run_name> \
  --checkpoint <model_XXXX.pt>
```

Default logs/checkpoints live under `Lite3_rl_training/legged_gym/logs/`.

## Deployment (simulation or real robot)

Location: `Lite3_rl_deploy/`

Start here:
- `Lite3_rl_deploy/README_EN.md` (English)
- `Lite3_rl_deploy/README.md` (Chinese)

Notes:
- The deploy binary loads `Lite3_rl_deploy/policy/ppo/policy.onnx` by default.
- Convert PyTorch checkpoints with `Lite3_rl_deploy/policy/pt2onnx.py`.
- Sample checkpoints are stored in `Lite3_rl_deploy/policy/`.

Quickstart (most common build flags):

Sim-to-sim (x86, with simulator):

```bash
cd Lite3_rl_deploy
mkdir -p build && cd build
cmake .. -DBUILD_PLATFORM=x86 -DBUILD_SIM=ON -DSEND_REMOTE=OFF
make -j
```

Run (two terminals):

```bash
# Terminal 1 (choose one)
cd Lite3_rl_deploy/interface/robot/simulation
python pybullet_simulation.py
# or
python mujoco_simulation.py
```

```bash
# Terminal 2
cd Lite3_rl_deploy/build
./rl_deploy
```

Sim-to-real (arm, no simulator):

```bash
cd Lite3_rl_deploy
mkdir -p build && cd build
cmake .. -DBUILD_PLATFORM=arm -DBUILD_SIM=OFF -DSEND_REMOTE=OFF
make -j
```

`Lite3_rl_deploy` is tracked as a git submodule. If you clone this repo from scratch:

```bash
git clone --recurse-submodules <repo-url>
# or, inside an existing clone:
git submodule update --init --recursive
```
